Findings:
[SEVERITY medium] internal/control/ingest.go:125-129 + internal/ledger/ledger.go:318 — Usage is only checked to be >= 0. Two ingested rows near MaxInt64 make SQLite's SUM() fail with 'integer overflow', which breaks Summary for every group (account, host, model, ...) over that range, for ALL accounts. That takes down /control/v1/usage, the widget and the plugin's 24h totals. group=day silently wraps negative in Go (ledger.go:385) instead. Any single ingest host, including a buggy transcript, can do this. — evidence: control TestReviewIngestRejectsImplausibleUsage (200 for MaxInt64); ledger TestReviewSummaryOverflowFromHugeUsage ('SQL logic error: integer overflow') — minimal fix: in ingest, reject any token field above a sane per-record cap (e.g. 1e9) and also check the claudelog sum at claudelog.go:428 for overflow; optionally use TOTAL() in aggCols.

[SEVERITY medium] internal/control/ingest.go:135-146 + internal/quota/ingest.go:44 — Snapshot windows are not validated or clamped on ingest, while the poll path clamps them with clampFrac (quota.go:294). A pushed used_frac of -5 is stored, so policy sees large headroom and admits background work on a reserved account; empty kinds are accepted too. — evidence: control TestReviewIngestValidatesSnapshotWindows (200); quota TestReviewIngestSnapshotClampsFractions (stored -3 and 7) — minimal fix: in validateIngest, reject used_frac outside [0,1] (and NaN), an empty kind and window_seconds < 0; and/or clampFrac each window in IngestSnapshot.

[SEVERITY low] internal/control/ingest.go:143 — A snapshot dated up to 5 minutes in the future is stored with that FetchedAt. Every genuine snapshot until then counts as not newer and is ignored, so one host with a fast clock freezes the account's quota view (e.g. at 0% used) for about 5 minutes. Snapshots are also not bound to the pushing client or host, so any ingest key can do this to any agent account (spec trust model, but worth noting). — evidence: control TestReviewFutureSnapshotFreezesAccount (SnapshotsIgnored=1 for a real later snapshot) — minimal fix: store min(FetchedAt, server now), or order snapshots by server receive time.

[SEVERITY low] internal/control/ingest.go:116 — Record IDs are only checked to be non-empty. A 1 MiB ID or one containing NUL or newline characters is stored as the primary key. — evidence: control TestReviewIngestBoundsRecordID — minimal fix: require ^[A-Za-z0-9:._-]{1,128}$ (claudelog IDs are 'claude:'+32 hex characters).

[SEVERITY low] internal/control/ingest.go:114-133 — started_at is not validated. A zero time is stored as a large negative epoch and is silently excluded from every since-window; a far-future time is counted in every 'last 24h' summary until that date. — evidence: control TestReviewIngestValidatesTimestamps — minimal fix: reject a zero started_at and anything more than about 5 minutes after server now (optionally also anything older than N days).

[SEVERITY low] internal/control/ingest.go:49 — json.Decoder.Decode is called without an EOF check, so trailing bytes after the first JSON value (a second object or garbage) are ignored and the request is written. Unknown fields are also accepted silently. — evidence: control TestReviewIngestRejectsTrailingGarbage (200, 1 row) — minimal fix: after Decode, require dec.Decode(&struct{}{}) == io.EOF (and optionally call dec.DisallowUnknownFields()).
